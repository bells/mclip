# v0.2.0 第一轮界面审查

日期：2026-09-06；源码：9386d2a；范围：桌面应用七窗口及 Preferences 六页。交付为 OpenSpec 提案，未修改产品代码。先完成主观/源码审查，再运行机械扫描；不把本记录称为已完成的双独立审查。

## 结论与保留项

mclip 的基础方向适合高频剪贴板工具：固定窄主窗口、独立详情、系统字体、青绿交互、即时保存、紧凑 keycap footer 都应保留。这轮的最大收益来自归类、文字和状态层级，以及转换结果窗口的实际布局修复，无需重做整套视觉。

三个优点：主窗口与preview分离，不牺牲列表密度；Preferences已具有搜索、语义switch和串行保存；置顶和隐私有独立状态及原文复制边界。新增能力应延续这些优点。

## 用户四项要求的具体方案

1. **托盘菜单**：偏好设置… / 分隔线 / 退出 mclip。保留左键切换与窗口ready，菜单跟随中英日设置。
2. **记事本 m**：同画布整体放大约8%-10%。当前有效轮廓约16.5×20/24px，优先减少留白，不换logo、不只加粗。最终幅度以16/18/22px和原生图标比较为准。
3. **设置归类**：侧栏MCLIP改通用，原通用页改行为；外观集中语言、主题、图标、Logo、序号。历史负责保存类型、保留上限与展示数量。
4. **转换布局**：按类型分行，一次点击直接打开结果。单入口弹层需多一步，又增加非聚焦preview复杂度，本轮不采用。

```text
文本转换
JSON       [格式化] [压缩]
Base64     [编码]   [解码]
URL 组件   [编码]   [解码]
```

这是全能力示意，实际只显示后端判定适用且用户开启的动作。无适用操作不留空行。
