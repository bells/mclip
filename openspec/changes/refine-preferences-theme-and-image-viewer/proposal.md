## Why

v0.1.1 发布前的界面已经具备稳定的产品气质，但偏好设置横向过宽、浅色主题中的部分交互色语义不一致，图片详情又只能在受限 preview 与不同结构的图片查看器之间跳转。需要用一次低风险精修让设置更易扫描、双主题状态更可靠，并让同一套历史详情在普通窗口和最大化之间自然切换。

## What Changes

- 将偏好设置窗口收窄并适度增高，把通用页的语言、外观和菜单栏图标从同一横排改为纵向设置行，再按“界面”“启动与行为”“主窗口”分组。
- 将“存储 / Storage”页签改为“历史 / History”，并按保存类型、最大记录数、主窗口条数、历史分组条数排列设置项；继续保持即时生效和即时保存，不增加保存或取消按钮。
- 校准浅色与深色主题的语义色：浅色选中态保持完整青绿色系，开关使用主题 token，强调与危险按钮使用各自主题可读的前景色；不改变现有冷绿中性色、暖金元信息、青绿交互和红色危险色体系。
- 保留 `preview` 与 `preview-detail` 的独立、不可聚焦窗口职责，不把它们直接改造成可聚焦或可最大化窗口；专用 `image-viewer` 作为原生宿主完整复用历史详情的标题栏、图片内容区和底部元信息区。
- 从图片历史详情进入查看器时直接最大化；标题栏中的最大化按钮同步变为恢复按钮，恢复后回到约 `720×520` 的普通详情窗口，同时保留关闭、`Escape` 和删除动作。
- 查看器打开期间主窗口保持显示和原位置，但临时退出托盘弹窗的置顶层级，使最大化历史详情自然覆盖主窗口；关闭或打开失败时恢复主窗口原有置顶与失焦隐藏行为。仅隐藏旧的 `preview` / `preview-detail`，不增加系统最小化，避免 `skipTaskbar` 窗口失去可恢复入口。
- 为普通图片详情补齐轻量的加载与失败反馈，同时不改动历史分组 hover、pointer 命中和 preview 请求失效机制。

## Capabilities

### New Capabilities

- `image-viewer-window`: 定义专用图片查看窗口的普通尺寸、最大化与恢复、关闭、图片加载反馈，以及与 preview 家族之间的职责边界。

### Modified Capabilities

- `appearance-settings`: 增加双主题交互状态的语义色与对比要求，并规范通用设置的分组与纵向布局。
- `dialog-window-chrome`: 调整偏好设置窗口的紧凑尺寸与固定窗口控制行为。
- `history-display`: 明确“历史”设置页签的命名、设置项顺序和即时保存行为。

## Impact

- 前端：`PreferencesWindow`、共享历史详情渲染、`FullscreenImageViewer`、图片查看器完整历史项 payload、语义主题 token、Tailwind class 映射和中英文文案。
- Tauri：`preferences` 与 `image-viewer` 的预声明窗口尺寸，以及图片查看器直接最大化、恢复、关闭和主窗口失焦保护的 typed command 边界。
- 测试：更新偏好设置布局、主题 token、图片查看器窗口行为和双语文案的回归覆盖。
- 兼容性：不改变设置数据结构、历史数据、剪贴板行为或 preview 定位；仅把前端跨窗口 viewer 事件 payload 从图片路径信息扩展为完整图片历史项，不改变 Rust 持久化契约，也不引入新的运行时依赖。
