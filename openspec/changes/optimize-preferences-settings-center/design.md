## Context

`PreferencesWindow.tsx` 当前在一个约 600×480 的固定辅助窗口内，用四个顶部页签承载通用、历史、隐私和 Agent CLI。控件、异步状态、即时保存队列和全部页面渲染集中在同一组件中；随着敏感内容保护和文本快速操作加入，继续增加页签会降低可发现性，也会让行级状态、搜索和测试难以扩展。

本次参考 ChatGPT 的左侧导航/右侧设置行和 Zero 的搜索、页面标题、分组方式，但视觉上继续使用 mclip 的冷绿中性色、暖金元信息、青绿交互和红色危险色语义。Preferences 仍是按需创建并保留的独立 Tauri 辅助窗口，设置仍通过现有 Rust `save_settings` 边界整体保存，前后端 `AppSettings` 必须对称，所有变更立即生效。

## Goals / Non-Goals

**Goals:**

- 建立能容纳现有与近期设置的双栏设置中心，并让用户可通过分类或本地搜索直达具体控件。
- 把通用、外观、历史、隐私、文本操作和 Agent CLI 形成稳定的信息架构。
- 保留即时应用/即时保存，同时将保存进度和错误限制在相关设置行，不让页面闪烁或整体禁用。
- 为桌面文本操作增加 JSON、Base64、URL 组件三个分组开关，保持旧配置与 CLI 兼容。
- 保留隐私功能的真实边界：具体开关、原文复制真相、明文持久化披露和平台能力状态。
- 将导航、元数据、保存控制器和页面拆成可独立测试的 TypeScript 模块，不引入 `any` 或新的运行时依赖。

**Non-Goals:**

- 不新增总的“隐私模式”，也不把启发式遮罩描述为静态加密。
- 不增加按时间清理历史、清空时保留策略、暂停监听或可编辑全局快捷键。
- 不改变 CLI `transform`、quick-action 结果窗口、替换确认、输入输出上限或 Rust 转换算法。
- 不把 Preferences 变成 eager WebView，不改变其它辅助窗口、preview 定位或剪贴板监听架构。
- 不复制 ChatGPT 的深色品牌外观或 Zero 的浅绿侧栏，也不引入装饰性插图和无关动效。

## Decisions

### 1. 使用固定双栏设置中心，而不是继续增加顶部页签

Preferences 默认和固定逻辑尺寸调整为约 820×600。标题栏下方使用约 220 像素侧栏和自适应内容列：侧栏包含搜索与“mclip / 工具”两组导航，内容列包含页面标题、说明和可滚动设置组。

```text
┌──────────────────── mclip Preferences ────────────────────┐
│ ┌───────────────┬───────────────────────────────────────┐ │
│ │ 搜索设置…      │ 外观                                  │ │
│ │               │ mclip 的主题与主窗口显示               │ │
│ │ mclip         ├───────────────────────────────────────┤ │
│ │  常规         │ 界面                                  │ │
│ │ ▌外观         │  主题                         [跟随系统]│ │
│ │  历史         │  菜单栏图标                       [图标]│ │
│ │  隐私         │ ───────────────────────────────────── │ │
│ │ 工具          │ 主窗口                                │ │
│ │  文本操作     │  显示 Logo                         [●] │ │
│ │  Agent CLI    │  显示序号                         [●] │ │
│ └───────────────┴───────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

侧栏激活项使用现有 selection surface 加一条 2 像素青绿“clipboard spine”内侧轨道作为唯一识别性元素；其它结构保持安静。字体不引入下载依赖：标题与正文使用平台 UI 字体，应用标识、路径和来源 ID 使用现有等宽字体。深色主色沿用 `#f8fafc / #d5dde8 / #9aa7b6` 与 `#73d0c8`，浅色沿用 `#0f1f1a / #25372f / #445951` 与 `#0b6f67`，所有组件继续从语义 token 取色。

固定尺寸优先于可缩放窗口，因为当前自定义标题栏只提供关闭动作，且 mclip 是紧凑托盘工具；820×600 已能在常见 1366×768 Windows 工作区内完整容纳。超长中文/英文、权限状态和 CLI 路径在内容列内滚动或换行，不扩大原生窗口。

备选方案是保留 600×480 顶部页签，改动更小但不能解决搜索和扩展性；另一个方案是可缩放双栏窗口，但会要求补齐最大化/恢复控件和更复杂的窄宽导航，本次没有足够产品收益。

### 2. 页面与导航由同一份本地元数据生成

新增纯 TypeScript 设置描述符，使用稳定 `settingId`、`destinationId`、标题、说明、搜索别名和 `focusTargetId`。页面顺序固定为：

- `mclip`：通用、外观、历史、隐私；
- `tools`：文本操作、Agent CLI。

导航、搜索索引、搜索结果路径和页面控件 ID 都从这份描述符生成，避免文案与实际控件漂移。搜索只在当前语言的静态标题、说明、页面路径和受控别名上做 trim 后的不区分大小写子串匹配；不索引设置值、剪贴板内容、来源应用 ID、安装路径或错误详情。

选择搜索结果后先切换页面，再在下一帧滚动并聚焦目标控件。`Escape` 在搜索有内容时只清空搜索；搜索为空时沿用隐藏 Preferences 的行为。备选的模糊搜索库没有必要，静态设置数量有限，新增依赖和排序不确定性反而降低可预测性。

### 3. 将窗口编排、页面与设置控件拆开

`PreferencesWindow` 只负责窗口级生命周期、加载设置、平台状态和关闭行为。新增设置中心 shell、导航/搜索模块、页面组件、共享 `PreferenceRow` / `PreferenceSwitch` / `PreferenceSelect` / `PreferenceActionRow`，以及即时保存 hook。

布尔控件统一使用右侧开关并暴露 `role="switch"`、`aria-checked`；枚举使用原生 select 或现有可访问 listbox；数值继续允许空字符串编辑中间态并在合法范围内即时提交；状态与危险动作不会伪装成开关。页面标题使用 `h1`，设置组使用 `section` 和可关联的 `h2`，导航使用 `nav`，搜索结果为可键盘操作的列表。

备选方案是在现有单文件中抽取少量 class，但仍会保留状态、搜索索引和页面渲染耦合，不利于行为测试。

### 4. 复用串行保存协议，增加 keyed feedback 而不是整页 loading

新增 `usePreferenceSaveController` 封装 `latestSettingsRef`、串行 Promise 队列、全局 revision 和按 `settingId` 的 `idle | pending | saved | error` 状态。每次编辑先乐观更新内存和 UI，再把完整、归一化的 `AppSettings` 快照排入现有 `saveSettings`；保存期间只禁用必须防止重复执行的动作，不禁用导航、页面或其它字段。

成功响应只在没有更新 revision 时同步后端规范化结果；失败只在该请求仍是最新 revision 时回退到请求前快照，并在对应行显示可访问错误。后续成功保存会清除旧错误。`settings-updated` 回声在本地保存仍 pending 时不覆盖乐观状态，队列结束后以最新成功结果为准。

继续整体保存而不是新增 patch IPC，能保持 Rust 命令和持久化路径稳定。备选的并行字段保存会产生旧快照覆盖新值的竞态，不采用。

### 5. 隐私页保留具体边界，不引入总开关

`maskSensitiveContent` 已经准确表达“默认展示是否遮罩”；`ignoredSourceAppIds` 表达“哪些来源不进入历史”，两者语义和风险不同，不能被一个总开关同时关闭。隐私页继续展示：

- 敏感内容遮罩开关与“原文仍在本地保存、复制仍使用原文”的说明；
- 来源检测能力状态、精确标识输入和已忽略列表；
- 用户显式触发的旧历史重新分类动作。

搜索元数据只包含这些控件的名称和说明，不包含已配置来源标识。平台不可用时展示稳定能力说明，不声称排除已执行。

### 6. 文本操作设置使用分组结构，并只过滤桌面入口

在 Rust 与 TypeScript 增加对称结构：

```ts
type TextQuickActionSettings = {
  json: boolean;
  base64: boolean;
  urlComponent: boolean;
};
```

`AppSettings.textQuickActions` 默认三个字段均为 `true`。Rust 使用 serde default，前端 normalize 对嵌套对象逐字段合并，因此旧 `settings.json` 无需迁移写回即可保持当前行为。后端 sanitize 只接受布尔值并补齐缺省值。

映射固定为：JSON 控制 `jsonPrettify/jsonMinify`，Base64 控制 `base64Encode/base64Decode`，URL 组件控制 `urlComponentEncode/urlComponentDecode`。`TextQuickActions` 先根据设置过滤 Rust 返回的适用动作；全部关闭时不请求适用性并不渲染该区域。敏感文本未显式 reveal 时仍不提供操作，设置不能绕过 reveal 边界。

设置随 item/group preview typed payload 传入独立预览窗口，并在分组详情 payload 派生时继续携带；打开 Preferences 仍会关闭旧 preview，所以不增加额外跨窗口订阅。CLI `transform` 是显式工具入口，不读取这组桌面展示偏好。

备选的单一主开关不能满足用户单独关闭 Base64 或 URL 的需求；逐 action 六个开关又会暴露实现级细节并增加噪声，因此采用三类分组。

### 7. 不引入新的 UI 或状态库

设置数量有限，React state、纯元数据函数和现有 Tailwind 4 / `uiStyles.ts` 足够实现。复用当前语义 token、Tauri IPC facade 和辅助窗口 ready 协议，避免为导航或开关引入组件库后产生视觉不一致、包体增长和 WebView 行为差异。

## Risks / Trade-offs

- [固定 820×600 比现有窗口更占屏幕] → 保持内容密度、在常见 1366×768 工作区内验证完整 frame，并让内容列独立滚动；不进一步追随参考截图的大尺寸。
- [拆分组件可能破坏现有 source-shape 测试] → 把测试迁移为元数据、DOM/行为和数据契约断言，避免依赖单文件字符串布局。
- [整体设置保存的失败回退可能覆盖随后编辑] → 用串行队列和 revision，只允许最新请求更新或回退可见状态。
- [搜索索引遗漏新增设置] → 为描述符与实际渲染 setting IDs 建立双向覆盖测试，中英文分别验证。
- [文本操作设置未及时传入某个 preview 路径] → 扩展 item/group/detail payload 类型并覆盖单条详情、分组 hover 详情和设置全部关闭的回归测试。
- [隐私页在重排中弱化安全披露] → 对明文持久化、显式 reveal、来源能力和无总开关建立独立契约测试。
- [参考产品导致 mclip 视觉身份变淡] → 只借用信息架构，颜色、圆角、密度、字体和 active spine 都从 mclip 现有系统派生。

## Migration Plan

1. 先加入 `textQuickActions` 的 Rust/TypeScript 默认值、serde 兼容、normalize/sanitize 和数据契约测试；旧设置文件读取时仅在内存补齐，不强制改写。
2. 增加纯导航/搜索元数据、保存控制器和共享设置行组件，再逐页迁移现有控件，保持每一步可编译。
3. 扩展 preview payload 并接入文本操作过滤；桌面全部默认开启，确保升级后行为不变。
4. 切换到双栏 shell 和 820×600 窗口描述符，更新双语文案、样式与窗口契约测试。
5. 运行前端/Rust/根测试、严格 OpenSpec 验证和 macOS Preferences smoke；Windows 视觉与辅助窗口行为由 CI 和真机 smoke 最终确认。

回滚 UI 时可以恢复旧 Preferences 组件和窗口尺寸；新增 `textQuickActions` 字段可安全保留，也可移除而不影响旧字段和历史数据。因为默认值保持当前行为，回滚不需要迁移历史或设置文件。
