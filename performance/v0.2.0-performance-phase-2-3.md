## 第二阶段：减少可证明的分配

- `agent_cli.rs` 的选择和搜索结果保存记录引用；普通记录和显式 reveal 使用 `Cow::Borrowed`，仅需遮罩的敏感记录创建 owned 副本。格式化借用文本/图片路径，文件路径拼接仍拥有结果。JSON 在已有输出尾部追加换行，避免复制整份结果。
- `history.rs` 的 SHA-256 摘要直接格式化，不再为每个字节创建临时字符串；去重直接比较 ID，去掉多余 ID 复制。
- 四个敏感检测正则原本已用 `LazyLock<Regex>`，保留 64 KiB、detector v1 和固定遮罩规则。原始记录不被展示流程修改，raw/reveal 仍仅对当前调用显式揭示。

基准使用 500 条合成文本，每条 `text` 与 `displayText` 均为 256 次重复的多语言 fixture。每项预热一次、5 批、每批 20 次，下表耗时为各批单次均值的中位数。计数 allocator 只在测试构建中启用并委托 System，按当前线程记录 allocation/reallocation 次数与请求字节；**字节总量包含重分配请求，并非峰值内存、RSS 或存活内存**。JSON/list 测量不含文件 I/O，也不代表真实 CLI 进程端到端延迟。

| 热点 | 每次分配次数 前→后 | 每次累计请求 bytes 前→后 | 耗时中位数 前→后 |
| --- | ---: | ---: | ---: |
| 分类（普通长文本，正则已预热） | 0 → 0 | 0 → 0 | 11.84 → 11.79 µs |
| SHA-256 十六进制格式化 | 35 → 1 | 368 → 64 | 4.85 → 0.90 µs |
| 搜索 500 条，无匹配 | 3,004 → 2,503 | 15,400,892 → 12,840,884 | 7.13 → 7.10 ms |
| list JSON 500 条 | 3,023 → 21 | 36,771,673 → 10,675,184 | 3.02 → 2.12 ms |
| context 5 条 | 109 → 74 | 445,704 → 315,598 | 23.92 → 19.02 µs |
| 合并 500 条，含输入 clone | 1,506 → 1,505 | 5,311,652 → 5,311,641 | 197.49 → 194.35 µs |

搜索、合并和变换的耗时差不足以宣称提升。列表 JSON 的分配总量下降约 71%，更直接地证明了减少整条历史复制的收益。所有批次保存在 [core-baseline.json](v0.2.0-core-baseline.json) 和 [core-optimized.json](v0.2.0-core-optimized.json)。时间结果只描述这次合成工作负载，未执行多轮交错采样或显著性检验。

### 依赖与结构决策

当前仍是单 Cargo 包、两个 binary。CLI 调用共享库中的 history、settings、clipboard 等模块；直接拆 crate 会涉及平台 adapter 和持久化接口。feature 图审计没有发现直接 `tokio/full` 或重复 HTTP 客户端，reqwest 已禁用默认 feature 并使用 Rustls。`otool -L` 显示 CLI 链接系统 AppKit/WebKit，而不是把这些 framework 复制进包中。

没有实施拆分原型，不能声称拆分已经验证无收益；现有 1.67 MB CLI 和 LTO 结果不足以证明它是优先的尺寸瓶颈。暂保留结构，后续若要拆分，先为目标平台独立构建 adapter 原型并比较链接产物。

图像读取使用 `image::load_from_memory`，图像格式还涉及 arboard/Tauri 统一 feature 的 PNG/JPEG/TIFF/ICO/BMP。不能仅因直接声明较少就移除传递格式支持。macOS changeCount、Windows 原生事件与 Linux broker 保持，Linux signature-first 优化仍由原 Linux change 跟踪。本轮没有新增运行时依赖。

## 第三阶段：资源与实际渲染热点

前端 AppHeader、Preferences 和 Rust app 风格托盘图标复用仓库已有的 `src-tauri/icons/128x128@2x.png`（256px、67,512 bytes），替代内嵌的 1024px 原图（912,547 bytes）。每处原始资源差为 845,035 bytes；不重生成图像，原始 artwork 与原生 ICNS 保留。前端/后端两处嵌入共同解释了 Mach-O 的主要下降。

浏览器 DPR2、22/32 CSS px、深浅背景完成原图与候选并排核查，均显示清晰、同一图形。复现脚本生成 `src-tauri/target/list-benchmark-icons-2x.png`。此为 Chrome 渲染证据，原生菜单栏 HiDPI、系统主题切换和实际尺寸仍需 macOS smoke。

bundle 分析器现在覆盖 main、preview、preview-detail、image-viewer、about、preferences、quick-action 七路由，递归统计全部文件 raw/gzip/SHA-256，按路由去重静态 JS/CSS/图片，并报告 source map、重复文件和缺失资源。保留原来 JS-only `rawBytes/gzipBytes` 字段，新加总资源字段；各路由包含共享 bootstrap，不能直接相加当作 dist 总量。

当前 dist raw 为 600,264 bytes，逐文件 gzip 合计为 249,296 bytes；bootstrap JS gzip 为 73,600 bytes，满足原有 75 KiB 预算。没有 map、重复内容文件或缺失引用。此 gzip 是分析指标，不等于 Tauri 内嵌压缩算法或网络传输承诺。完整清单见 [bundle-baseline.json](v0.2.0-bundle-baseline.json) 和 [bundle-optimized.json](v0.2.0-bundle-optimized.json)。

### 列表优化与测量

识别到普通长文本在每次选中变化时重复执行全文 code-point 分配。现在先通过 UTF-16 长度上界排除超长 Emoji 候选，再保留原有 16 code-point 语义；`HistoryListText` 使用默认 `React.memo` 比较稳定的 primitive props，避免重复计算。没有给包含闭包的整行添加自定义比较器。

搜索先筛选再创建带 renderId/position 的对象；普通无空格查询按字段搜索，避免拼接完整副本，含空格的跨字段短语继续走原先拼接逻辑。原始序号、Unicode 大小写和文件路径/图片维度搜索保持，不维护额外全文索引。

Chrome 152.0.7977.83，production React profiling 构建，实际 HistoryList，合成长文本/文件/图片（图片 IPC 使用 Tauri mock）。每个规模测量 30 次选中更新和 30 次搜索，选中耗时包含同步 React commit 和强制布局；不包括浏览器绘制呈现、原生 IPC 和 WebView 创建。

| 总记录数 | 选中更新中位数 前→后 | 选中更新 p95 前→后 | React 中位数 前→后 | 搜索中位数 前→后 |
| --- | ---: | ---: | ---: | ---: |
| 10 | 1.4 → 0.2 ms | 2.3 → 0.9 ms | 1.3 → 0.1 ms | 0.4 → 0.5 ms |
| 50 | 6.2 → 0.3 ms | 8.1 → 0.7 ms | 6.0 → 0.1 ms | 2.1 → 1.9 ms |
| 500 | 61.4 → 2.1 ms | 62.2 → 3.2 ms | 59.7 → 1.2 ms | 21.7 → 20.1 ms |

DOM 数量前后分别保持 82/322/3,022，容器 scrollHeight 保持 700/1,768/17,608 px（10 条时受 700px 测试容器下限影响）。浏览器通过 pointer、focus、Enter 复制回调和有限 anchor 坐标断言，无 pageerror。500 是本次总条数，含 5 条置顶，并非“500 普通项加所有保留置顶”的绝对极限。完整样本见 [render-baseline.json](v0.2.0-render-baseline.json) 和 [render-optimized.json](v0.2.0-render-optimized.json)。

选中热点已明显下降，暂不引入虚拟列表，保留混合行高、DOM 定位与独立窗口模型。搜索提升很小，仍有长文本扫描成本；暂不增加常驻文本缓存或延迟搜索。没有 debounce 历史 delta 或 Preferences 即时保存。真实跨窗口 hover、键盘自动滚动、原生 resize 和 WebKit 帧时间仍需设备验证。

- `pnpm run check`：前端构建、Rust fmt/test/check/clippy 全通过；Rust 223 单元测试、21 CLI 集成、9 安装测试通过，2 项 opt-in 测试保持 ignored。核心合成 benchmark 另行显式运行通过。
- Node：既有与新增行为回归 218 项通过，新增 bundle 分析器合成文件测试 1 项通过（共 219 项）；覆盖七路由、共享资源去重、map/重复文件发现和缺失资源报错。
- release CLI：`compare-cli.mjs` 使用临时合成历史，对第一阶段和新二进制执行 48 组 stdout/stderr/exit status 字节对比，全一致；另检查默认遮罩与 reveal。包含多种格式、meta、agent、help/version、变换和错误路径，不写系统剪贴板。
- 独立 profiling TSX 严格类型检查、browser harness、实际 dist 分析通过。常规构建未包含测试 harness。
- 最终本地 release app/DMG 构建和严格签名验证通过。OpenSpec 全量 strict 校验 26 项通过，`git diff --check` 通过；网站未改，无需重复 site gate。

从仓库根目录运行：

```sh
# Rust synthetic benchmark：不读取用户历史
cargo test --locked --manifest-path src-tauri/Cargo.toml --release --lib synthetic_hot_paths -- --ignored --nocapture

# 真实前端产物清单
pnpm run build
node scripts/performance/analyze-bundle.mjs

# production React profiling harness；需要已有 Playwright 和浏览器
node scripts/performance/build-list-benchmark.mjs
MCLIP_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs MCLIP_BROWSER_EXECUTABLE=/absolute/path/to/chrome node scripts/performance/run-list-benchmark.mjs
pnpm exec tsc --noEmit --strict --skipLibCheck --target ES2023 --module ESNext --moduleResolution bundler --jsx react-jsx scripts/performance/list-benchmark.tsx

# 顺序构建桌面和独立 CLI，再 bundle；与第一阶段保持同一协议
pnpm run tauri:build --no-bundle -- --locked
cargo build --locked --manifest-path src-tauri/Cargo.toml --release --bin mclip-cli
node scripts/performance/compare-cli.mjs src-tauri/target/size-audit-v0.2.0/size-z/mclip-cli src-tauri/target/release/mclip-cli
pnpm exec tauri bundle --bundles app,dmg --ci
codesign --verify --deep --strict --verbose=2 src-tauri/target/release/bundle/macos/mclip.app
```

基线使用第一阶段生产源码与相同合成 harness；core 和 render JSON 保存各自优化前后采样，最终额外 browser smoke 不替换这组对比样本。构建产物快照保存在 ignored `src-tauri/target/size-audit-v0.2.0/phase-2-3/`，第一阶段 `size-z/` 保留。复现基线需同时保留本轮新增的测试 harness。构建顺序可导致库重新编译，耗时不作为编译性能基准。

## 剩余验收和尺寸优先级

本轮没有执行 native idle CPU、进程家族 RSS、五次冷/热启动协议，不能从分配和包大小推导其改善。macOS 原生七窗口、HiDPI、安装/异常路径，以及 Windows source check/真机、Linux 构建与命名会话运行验证均保留 OpenSpec 4.2–4.4；未改 Windows 专属代码，当前结果不能外推至其它平台。

后续尺寸候选首先是 1.62 MB ICNS 的无损压缩/分辨率内容审计与 app 内 CLI 的实际分发策略评估；均须先确认原生图标和安装契约，不能直接删除。只有进一步链接分析显示明显死重时才做 CLI adapter 拆分实验。3–5 MB 继续作为探索目标，不以删功能或未验证的依赖裁剪达标。
