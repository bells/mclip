## 基线方法

先按原配置执行 `pnpm run tauri:build --bundles app,dmg`。桌面编译成功（51.70 s），sandbox 内 DMG 创建返回 `hdiutil: create failed - 设备未配置`。随后显式构建 CLI：

```bash
cargo build --locked --manifest-path src-tauri/Cargo.toml --release --bin mclip-cli
pnpm exec tauri bundle --bundles app,dmg --ci
```

CLI 构建 48.87 s；在获准的本地打包权限下 app/DMG 成功。首个命令未传 `--locked`，前后锁文件摘要核实一致。一个最初的 `pnpm run tauri:build -- --bundles app,dmg` 调用因把 bundles 参数转交 Cargo 而失败，不计作基线；正确形式让 Tauri 参数直接跟在 script 后。

优化候选使用：

```bash
pnpm run tauri:build --no-bundle -- --locked
cargo build --locked --manifest-path src-tauri/Cargo.toml --release --bin mclip-cli
pnpm exec tauri bundle --bundles app,dmg --ci
```

`z` 对照通过 `CARGO_PROFILE_RELEASE_OPT_LEVEL=z` 覆盖相同 profile，编译桌面和 CLI 时均使用。基线与候选快照保存在 ignored `src-tauri/target/size-audit-v0.2.0/`，包含完整 app、独立 CLI、DMG、dist 及逐文件字节数/SHA-256。编译耗时受缓存影响，不作为编译速度对比。

## 结果

最终采用 `opt-level="z"`、`lto=true`、`codegen-units=1`、`panic="abort"`、`strip=true`。候选仅改变 Cargo profile；Vite 显式压缩配置与原默认配置生成的全部文件逐个 SHA-256 相同。

| 产物（bytes） | 原 Release | s 候选 | z（采用） | 相比基线减少 |
| --- | ---: | ---: | ---: | ---: |
| app 内已签名桌面 Mach-O | 19,641,200 | 8,602,464 | 7,058,192 | 64.1% |
| 独立 Release CLI | 3,548,544 | 1,844,400 | 1,667,248 | 53.0% |
| app 内已签名 CLI | 3,546,032 | 1,851,808 | 1,675,680 | 52.7% |
| 完整 app（含 CLI、ICNS、签名） | 24,814,858 | 12,081,898 | 10,361,498 | 58.2% |
| DMG | 12,865,668 | 9,258,208 | 8,906,629 | 30.8% |
| 前端 dist（含 manifest、资源） | 1,444,812 | 1,444,812 | 1,444,812 | 0% |

DMG 从 **12.87 MB 降至 8.91 MB**，仍高于 **3–5 MB** 探索目标。Mach-O/CLI 的符号剥离和代码大小收益不会按同一比例映射到已压缩 DMG；后续需要单独验证资源与依赖收益。不得将 app 内已签名 binary 与签名前 binary 混算，独立 CLI 与 bundle 内重新签名的 CLI 也单列。

`s` 桌面/CLI 构建分别为 2m22s / 1m09s，`z` 分别为 1m40s / 1m01s。这些是有缓存的执行耗时，不能据此声称 z 编译更快。设置 profile 为 z 后另执行无环境覆盖的最终构建，1m27s 成功，确认仓库默认生效。

逐文件字节数与 SHA-256 见 [原始测量 JSON](v0.2.0-size-phase-1.json)。三个快照分别在 `src-tauri/target/size-audit-v0.2.0/{baseline,size-s,size-z}/`。选定 DMG 的 SHA-256 为 `7bd37399080752268b98c94577478cbb1fd7b792775937c97c112c9fa8d2dd84`；快照目录不进入 Git。

## 审计发现与后续排序

1. **编译 profile 空缺**：Cargo 原先使用默认 Release（opt-level 3、无跨 crate LTO、panic unwind、无显式 strip）。本阶段单独测量 profile 收益，避免与素材替换混算。
2. **大图标资源**：前端 `app-icon.png` 为 1024×1024、912,547 bytes；基线整个 dist 为 1,444,812 bytes，单图占约 63%。前端压缩已开启；简单配置 terser 或关闭已有关闭的 sourcemap 不会解决图片占比。后续优先验证按 UI 实际尺寸派生资源，保留 HiDPI 视觉和真实应用图标。
3. **包内 CLI 与 ICNS**：实际 app 包含两个 binary，另有 1,623,981-byte `icon.icns`，没有额外官网、测试或 target 目录。Preferences 安装流程下载带 SHA-256 的 Release CLI；包内 CLI 是否需要保留值得评估，但本阶段保持原分发内容，避免将移除文件算作纯编译优化。
4. **CLI 对桌面库的依赖**：当前不是三个 crate，而是 `mclip` 包内两个 binary；CLI 通过共享桌面库入口运行。后续先评估领域模块/平台适配层拆分的实际链接收益，不为目录整齐先迁移 workspace。
5. **依赖已有裁剪**：reqwest 已使用 `default-features=false` 与 Rustls；不存在并列 ureq。Tokio 为 Tauri/HTTP 传递依赖，Tauri 自身启用多线程 runtime，根 manifest 简单追加精简 feature 无法关闭传递 feature。image 直接只启用 PNG/JPEG，但 macOS arboard 需要 TIFF、Tauri image-ico 引入 ICO/BMP；分别核实平台用途再裁剪。
6. **已做的热点优化**：四个敏感正则均为 `LazyLock<Regex>`；重复签名比较使用借用及 `clone_into` 复用字符串容量。现有窗口懒加载、revision delta、图片单飞缓存继续保留。
7. **测量缺口**：现有 bundle 分析器只列六个窗口，缺 quick-action，静态资源只列名称；后续补七路由和资源字节统计。基线 bootstrap JS gzip 为 73,593 bytes，在现有 75 KiB 门禁内。
8. **React 先测后改**：默认主列表 10/分组 50，但主列表配置可达 500 普通项加已有置顶，值得用合成混合行实测。禁止用丢失 delta 的防抖方式优化事件，或破坏 preview 的指针/高度/键盘契约。

## 验证边界

完成的验证：

- 三组真实 macOS arm64 Release 桌面/CLI 构建、app 与 DMG 打包，包内文件种类保持一致。
- `pnpm run check`：前端构建、Rust fmt、222 项单元测试通过（1 项显式性能 benchmark 按原约定 ignored）、21 项 CLI 集成测试和 9 项 CLI 安装集成测试通过、cargo check/clippy 通过。
- 修改 Vite 后 `node --test tests/*.test.mjs`：216/216 通过，包括 75 KiB bootstrap 和辅助路由加载边界。
- 基线、s、z 独立 release CLI 各 8 项 smoke：help/version、JSON minify、Base64 encode/decode（含 stdin）、URL encode/decode、非法 JSON 非零退出；使用不存在的临时历史路径，未创建历史文件，未访问系统剪贴板。
- `codesign --verify --deep --strict` 对 s/z app 成功；签名验证不等于 Gatekeeper/公证或 GUI 启动验证。
- Cargo/pnpm 两个锁文件摘要保持不变；所有 dist 文件摘要相同，没有 source map；OpenSpec 全量 strict 26/26 和 `git diff --check` 通过。

二进制体积下降不证明 CPU、RSS、启动延迟改善；`s`/`z` 还可能影响图像和文本吞吐。macOS 原生七窗口、剪贴板、异常路径与性能验收，以及 Windows/Linux 构建/运行时验证，保持待完成。没有公开网站变更，因此未重复 site gate；没有提交、归档或发布。

`panic=abort` 意味着 panic 后整个进程退出、不展开栈，panic hook 仍可执行；源码未发现应用自身 catch_unwind 依赖，但 Tauri/Tokio 的任务 panic 隔离语义会随之改变。`strip=true` 会减少符号诊断信息。普通 Result 错误处理保持，dev/test profile 保留原行为，测试成功不能替代 release panic 验证。
